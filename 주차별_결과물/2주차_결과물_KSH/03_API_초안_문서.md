# API 초안 문서

## 목적

SafeLink 앱과 Python 백엔드가 어떤 방식으로 데이터를 주고받을지 1차 기준을 정리한다.
이 문서는 다음 주 Android 연동과 백엔드 API 구현의 출발점으로 사용한다.

## 작성 기준

- `화면 흐름 요약본` 기준으로 서버 호출이 필요한 구간만 정리한다.
- 신기훈 결과물의 위험 카테고리, 위험도 계산 방식, 시나리오 초안 방향을 반영한다.
- 김우영 결과물의 데이터 항목, 기능 메모, 알림/설정 문구 방향을 반영한다.
- 1차 구현에서는 복잡한 기능보다 핵심 분석 흐름과 지원 연결 흐름에 집중한다.

## 1차 API 범위

현재 1차 구현에서 서버 연동이 필요한 핵심 기능은 아래와 같다.

- 위험 문장 분석 API
- 분석 결과 기반 지원 서비스 추천 API
- 서버 상태 확인 API

자가진단, 활동 기록, 설정 정보는 1차 기준으로 앱 내부 저장을 우선으로 보고, 서버 연동 API 대상에서는 제외한다.

## 전체 흐름

### 분석 흐름

`앱 -> 분석 요청 API -> 서버 분석 -> 결과 반환 -> 앱에서 결과/가이드/추천 연결`

### 추천 흐름

`앱 -> 위험 유형/위험도 전달 -> 추천 API -> 기관 목록 반환 -> 앱에서 추천 화면 표시`

## API 목록

### 1. 서버 상태 확인 API

#### 목적

- 앱이 서버 연결 가능 상태인지 확인
- ngrok 데모 환경에서 연결 점검용으로 사용

#### 요청

- Method: `GET`
- Path: `/health`

#### 응답 예시

```json
{
  "status": "ok",
  "service": "safelink-api"
}
```

### 2. 위험 문장 분석 API

#### 목적

- 사용자가 입력하거나 OCR로 추출한 텍스트를 분석
- 위험 표현, 위험 유형, 위험 점수, 위험 단계 반환

#### 요청

- Method: `POST`
- Path: `/analyze`

#### 요청 데이터 초안

```json
{
  "input_type": "text",
  "text": "지금 바로 계좌번호 보내. 안 보내면 큰일 나.",
  "source": "manual",
  "session_id": "optional-session-id"
}
```

#### 요청 필드 설명

- `input_type`
  - `text`: 직접 입력 텍스트
  - `ocr_text`: 스크린샷에서 추출된 텍스트
- `text`
  - 분석 대상 원문 텍스트
- `source`
  - `manual`, `ocr`, `demo` 등 분석 출처 구분용
- `session_id`
  - 같은 대화/같은 분석 흐름을 묶기 위한 선택 필드

#### 응답 데이터 초안

```json
{
  "risk_level": "high",
  "risk_score": 82,
  "risk_types": [
    "보이스피싱",
    "송금 요구",
    "긴급 압박"
  ],
  "matched_keywords": [
    "지금 바로",
    "계좌번호",
    "큰일 나"
  ],
  "matched_rules": [
    "금전 요구",
    "긴급 압박"
  ],
  "summary": "금전 요구와 긴급 압박 표현이 함께 감지되어 높은 위험도로 분류되었습니다.",
  "recommended_action": "즉시 송금이나 정보 제공을 중단하고 대응 가이드를 확인하세요."
}
```

#### 응답 필드 설명

- `risk_level`
  - `low`, `medium`, `high`
- `risk_score`
  - 0~100 범위 위험 점수
- `risk_types`
  - 분석된 위험 유형 목록
  - 예: `보이스피싱`, `로맨스 스캠`, `가스라이팅`
- `matched_keywords`
  - 감지된 핵심 키워드
- `matched_rules`
  - 감지에 사용된 규칙/패턴 이름
- `summary`
  - 사용자에게 보여줄 요약 설명
- `recommended_action`
  - 다음 행동 유도 문장

#### 분석 기준 반영 메모

- 신기훈 결과물 기준으로 위험도는 키워드/규칙 기반 점수 합산 구조를 사용한다.
- 위험 카테고리는 보이스피싱, 로맨스 스캠, 가스라이팅 계열을 우선 반영한다.
- 반복 압박, 금전 요구, 기관 사칭, 고립 유도 같은 하위 규칙은 `matched_rules`로 설명 가능하게 둔다.

### 3. 지원 서비스 추천 API

#### 목적

- 위험 분석 결과를 바탕으로 상황에 맞는 기관/지원 자원을 추천
- 앱의 지원 서비스 추천 화면에 표시할 데이터 제공

#### 요청

- Method: `POST`
- Path: `/recommend/institutions`

#### 요청 데이터 초안

```json
{
  "risk_level": "high",
  "risk_types": [
    "보이스피싱"
  ],
  "need_urgent_help": true
}
```

#### 요청 필드 설명

- `risk_level`
  - 분석 결과 단계
- `risk_types`
  - 감지된 위험 유형 목록
- `need_urgent_help`
  - 긴급 연결 우선 여부

#### 응답 데이터 초안

```json
{
  "institutions": [
    {
      "name": "경찰청",
      "phone": "112",
      "description": "긴급 신고가 필요한 경우 즉시 연결",
      "type": "긴급 신고",
      "action_label": "전화하기"
    },
    {
      "name": "한국인터넷진흥원",
      "phone": "118",
      "description": "스미싱 및 인터넷 사기 상담 지원",
      "type": "상담",
      "action_label": "상담하기"
    }
  ]
}
```

#### 응답 필드 설명

- `name`
  - 기관명
- `phone`
  - 전화번호
- `description`
  - 기관 역할 설명
- `type`
  - `긴급 신고`, `상담`, `지원` 등
- `action_label`
  - 버튼에 표시할 문구

#### 추천 기준 반영 메모

- 김우영 결과물 기준으로 기관 정보, 연락 방식, 안내 문구가 추천 화면에 들어가야 한다.
- institutions.json 초안이 정리되면 이 API는 해당 구조를 그대로 반환하는 방식으로 연결한다.

## 1차에서는 제외하는 API

아래 항목은 필요성은 있지만, 현재 1차 API 범위에서는 제외한다.

- 자가진단 결과 서버 저장 API
- 활동 기록 서버 동기화 API
- 사용자 계정/로그인 API
- 설정 저장 API
- 긴급 요청 접수 전용 API

이 기능들은 우선 앱 내부 저장 또는 후속 단계 확장 대상으로 둔다.

## 에러 응답 초안

### 공통 에러 형식

```json
{
  "error": true,
  "code": "INVALID_INPUT",
  "message": "분석할 텍스트가 비어 있습니다."
}
```

### 주요 에러 예시

- `INVALID_INPUT`
  - 입력 텍스트 없음
- `ANALYSIS_FAILED`
  - 분석 처리 실패
- `SERVER_ERROR`
  - 서버 내부 오류

## Android 연동 기준 메모

- 홈 대시보드에서 분석 입력 화면으로 이동
- 분석 입력 화면에서 `/analyze` 호출
- 분석 결과 화면에서 위험도와 요약 결과 표시
- 결과에 따라 대응 가이드 화면 또는 추천 화면으로 이동
- 추천 화면 진입 시 `/recommend/institutions` 호출 가능

## 최종 정리

SafeLink 1차 API는 크게 아래 3개로 정리한다.

- `GET /health`
- `POST /analyze`
- `POST /recommend/institutions`

핵심은 복잡한 계정 기능보다 `위험 감지 -> 결과 반환 -> 지원 연결` 흐름을 먼저 완성하는 것이다.
