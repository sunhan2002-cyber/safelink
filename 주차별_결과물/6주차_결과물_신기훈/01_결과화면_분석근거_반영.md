# 신기훈 6주차 결과물 01 - 결과 화면에 분석 근거 실제 반영

> 6주차 숙제 리뷰 대응. 통과 항목(엔진/구조)은 그대로 유지, 미흡 항목 4개를 처리:
> `DetectionResultScreen`에서 `sentenceRuleEvidences`/`situationalRuleEvidences`/
> `aiSummary`/`aiDetectedPattern`을 실제로 출력.

---

## 1. 리뷰 지적 사실관계

정확했다. 5주차까지 `sentenceRuleEvidences`/`situationalRuleEvidences`/`aiSummary`/
`aiDetectedPattern`은 `DetectionResult`에 데이터로는 다 있었지만, `DetectionResultScreen.kt`는
`matchedKeywords`(키워드 근거)와 `recommendedInstitutions`만 그리고 있었다 — 나머지 4개는
연결이 안 된 상태였다. "엔진/구조는 통과, 완료 기준(화면 반영)은 부분 통과"라는 판정 그대로.

## 2. 처리 내용

`DetectionResultScreen.kt`의 `DetectionResultContent()`에 3개 섹션을 추가했다. 위치는 기존
키워드 "분석 근거" 섹션 바로 뒤, "추천 기관" 섹션 바로 앞 (읽는 순서: 위험도 → 위험 유형 →
점수/키워드 근거 → **문장 규칙 근거 → 상황 규칙 근거 → AI 보조분석 결과** → 추천 기관).

| 섹션 | 표시 조건 | 내용 |
|---|---|---|
| 문장 규칙 근거 | `sentenceRuleEvidences.isNotEmpty()` | 기존 키워드 근거 카드와 동일한 스타일(좌측 컬러바) 재사용 |
| 상황 규칙 근거 | `situationalRuleEvidences.isNotEmpty()` | 위와 동일 스타일 |
| AI 보조분석 결과 | `aiSummary != null` (2차 `escalateToAI` 병합이 실제로 일어난 경우만) | `aiDetectedPattern`을 강조 제목으로, `aiSummary`를 본문으로 |

세 섹션 다 데이터가 없으면(대부분의 실제 케이스 — 지금은 순수 키워드 매칭만 하는 입력이
훨씬 흔함) 완전히 숨겨진다. 기존 "분석 근거"(키워드) 카드 컴포넌트를 그대로 재사용하는
`EvidenceCard()` 공통 함수를 하나 만들어서, `AnalysisEvidence(label, detail)` 구조에
맞춰 label을 먼저(조건 설명), detail을 부가 설명(매칭 문구/판정 조건)으로 배치했다 — 매칭
"문구"가 먼저 나오는 키워드 카드와는 반대 순서인데, 문장/상황 규칙 근거는 특정 한 단어가
아니라 "조건이 왜 성립했는지" 설명이 핵심이라 그렇게 정했다.

## 3. 문구

김우영 가이드에 이 3개 섹션에 대한 문구가 아직 없어서(확인함), 기존 화면 톤("분석 근거",
"감지된 위험 요소" 등)에 맞춰 "문장 규칙 근거" / "상황 규칙 근거" / "AI 보조분석 결과"라는
직관적인 제목으로 우선 넣었다. **최종 문구는 김우영이 다듬는 걸 전제**로 진행함 — 구조/연결
자체가 이번 리뷰의 핵심이라 판단.

## 4. 미리보기(Preview) 추가

기존 더미 4종은 전부 순수 키워드 매칭 시나리오라 새 섹션 3개가 하나도 안 보이는 상태였다.
`DetectionResultDummyData.evidenceShowcase`를 새로 만들어 3개 섹션이 전부 채워진 상태를
Compose Preview로 바로 확인할 수 있게 했다 — 가스라이팅 반복 패턴(상황 규칙)과 로맨스스캠
소액한정 요구(문장 규칙)를 한 입력에 합성한 시나리오다. 실제 한 대화에서 나올 조합은
아니지만, 새 UI 섹션들이 동시에 보이는 상태를 한 번에 점검하기 위한 미리보기 전용
데이터라 공식 41개 케이스와는 연결하지 않았다(주석에 명시).
