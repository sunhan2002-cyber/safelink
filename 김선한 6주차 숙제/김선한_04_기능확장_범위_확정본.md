# 김선한 6주차 숙제 04 - 기능확장 범위 확정본

## 1. 이번 숙제 범위

이번 숙제는 `김선한`과 `김재겸`이 맡은 기능확장 파트만 기준으로 정리한다.

즉 이번 파일의 범위는 아래와 같다.

- 스크린샷 분석 기능
- 백그라운드 감지 기능
- 두 기능이 기존 앱 흐름에 어떻게 붙는지

분석확장 세부 내용이나 문구 설계 세부 내용은 이번 파일의 직접 범위가 아니다.

## 2. 이번 숙제에서 실제로 한 것

- 기능확장 범위 정리
- 스크린샷 분석 흐름 정리
- 백그라운드 감지 구조 정리
- 구현 시작 전에 확정해야 할 항목 정리
- 설정 화면에 기능확장 관련 항목 추가

## 3. 이번 숙제에서 하지 않은 것

- 안드로이드 코드 구현
- OCR 실제 연결 구현
- 백그라운드 감지 서비스 실제 구현
- 알림 실제 동작 구현

즉 이번 숙제는 `개발 범위 확정`이 중심이지만, 설정 화면에 기능확장 관련 UI를 반영한 실제 코드 작업 1건이 포함된다.

## 4. 기능확장 포함 범위

- 스크린샷 분석 시작 위치 정리
- 스크린샷 입력 방식 정리
- OCR 결과를 기존 분석 흐름에 연결하는 방식 정리
- 백그라운드 감지 기능의 서비스 구조 정리
- 감지 후 알림 구조 정리
- 알림 이후 결과 화면/대응 가이드 화면 연결 기준 정리

## 5. 기능확장 제외 범위

- 완성형 OCR 정확도 개선
- 실시간 상시 감지 완성
- 전체 앱 대상 범용 감지 완성
- 배포 최적화
- AI API 운영 최적화

## 6. 김선한 역할 범위

- 기능확장 전체 기준 정리
- 스크린샷 분석 기능 명세 정리
- 백그라운드 감지 요구사항 정리
- 월요일 대면 회의에서 바로 구현할 수 있게 우선순위 정리

즉 김선한 역할은 `문서 담당만`이 아니라 `기능확장 구현 기준을 정하는 담당`이다.

다만 이번 숙제 결과물 자체는 `직접 구현 코드`가 아니라 `구현 준비 문서`다.

## 7. 김재겸 역할 범위

- 안드로이드 코드에 기능확장 구조 반영
- 스크린샷 분석 입력 흐름 구현
- OCR 연결 지점 구조 확보
- 백그라운드 감지 서비스/알림 구조 스켈레톤 반영

## 8. 월요일 대면 전까지 확정되어야 하는 결과

- 스크린샷 분석이 기존 흐름에 어떻게 붙는지 명확해야 한다.
- 백그라운드 감지 기능이 어떤 서비스 구조로 붙는지 명확해야 한다.
- 알림 클릭 이후 어느 화면으로 보낼지 명확해야 한다.
- 김재겸이 바로 구현을 시작할 수 있어야 한다.

## 9. 한 줄 결론

이번 기능확장 범위 확정본의 목적은 `무엇을 만들지 설명하는 것`이 아니라 `월요일부터 무엇을 바로 구현할지 확정하는 것`이다.
