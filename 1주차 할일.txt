- Safelink의 주제와 서비스 방향을 확정한다.
- 기본 로드맵과 세부 일정 초안을 완성한다.
- 최종 4개 역할 구조를 정리한다.

공통으로 해야 할 일
- 제 22회 한성공학경진대회 안내서 확인
- 최종 제출물 조건 확인
- 앱 한줄 소개 문장 확정
- 핵심 기능 우선순위 정리
- 백그라운드 감지 기능의 기술 리스크와 대안 검토
- GitHub 협업 환경 정리

최종 역할 구조

1. 기획 / 스펙 설계 / 문서화
- 서비스 목표와 문제 정의 정리
- 핵심 사용자와 사용 시나리오 설정
- 필수 기능과 선택 기능 구분
- 기능별 스펙 문서 작성
- README, 회의록, 기능 문서 정리
- 주간 산출물 문서화 및 버전 정리

2. 위험 감지 / 백엔드
- 위험 문장 및 관계 패턴 감지 기준 정리
- 위험도 분류 방식 설계
- 백그라운드 감지 흐름 검토
- 서버/API 구조 설계
- 감지 결과 처리 로직 연결

3. 프론트엔드 / UIUX
- 안드로이드 앱 화면 구현
- 화면 전환 및 네비게이션 구성
- 사용자 흐름 설계
- 와이어프레임 및 화면 구조도 작성
- 배너 알림 문구, 버튼 문구, 안내 문구 설계

4. 지원 연결 / 보안 / 기술 리스크 검토
- 상담 기관 및 복지 제도 연결 구조 정리
- 신청 동행 기능 설계
- 앱 잠금 및 생체인증 흐름 설계
- 민감 정보 보호 방식 정리
- 메신저 감지 제한사항과 구현 대안 검토

발표 및 제출물 작성 방식
- 발표 자료, 결과 보고서, 팜플렛, 소개 영상 구성은 팀 전체 공동 작업으로 진행한다.
- 각 역할은 자기 파트의 내용과 산출물을 제공하고, 문서 형식 정리와 초안 취합은 기획 / 스펙 설계 / 문서화 파트가 중심을 잡는다.
