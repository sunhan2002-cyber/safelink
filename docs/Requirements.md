# Requirements.md — Safelink

> 본 문서는 Safelink Android 앱의 기능 요구사항을 정의합니다.
> 모든 승인 기준은 EARS 문법을 준수하며, AI 구현 시 이 문서를 기준으로 합니다.

---

## 시스템 범위

| 항목 | 내용 |
|------|------|
| 플랫폼 | Android (앱) + Python (백엔드 위험 감지 API) |
| 저장 방식 | 로컬 저장 전용 (서버 계정 없음, 개인 데이터 외부 전송 없음) |
| 위험도 단계 | 앱 전체 통일: **주의 / 경고 / 긴급** 3단계 |
| 핵심 보안 원칙 | 앱 사용 사실 노출 금지, 최소 수집 원칙, 중립적 알림 문구 |

---

## 1. 기능 정의 (Feature Definition)

본 시스템은 위험한 관계에 처했거나 처할 위험이 있는 사용자가 스스로 위험을 인지하고, 즉각적인 도움에 연결되며, 실제 행동까지 이어지도록 지원하는 **보호형 Android 앱**입니다.

**기능 목록**

| 번호 | 기능명 | 한 줄 설명 |
|------|--------|------------|
| F-01 | 위험 관계 자가진단 | 체크리스트 기반 관계 위험 신호 점검 및 위험도 분류 |
| F-02 | 위험 대화 감지 | 붙여넣기/클립보드 텍스트에서 협박·통제 표현 탐지 |
| F-03 | 백그라운드 감지 + 배너 알림 | 위험 감지 시 단계별 배너 알림 발송 |
| F-04 | 대응 가이드 | 위험 감지 직후 즉각 취할 수 있는 행동 안내 |
| F-05 | 맞춤 지원 매칭 | 상황·위험 유형별 상담 기관·복지 제도 추천 |
| F-06 | 신청 동행 | 지원 제도 신청 절차·서류·방법 안내 |
| F-07 | 긴급 도움 요청 | 공공기관 즉시 전화 연결 + 지인 문자 발송 (선택) |
| F-08 | 상황 기록·조회 | 위험 상황 메모 저장 및 감지 기록 조회 |
| F-09 | 보안 기능 | 비밀번호 잠금, 생체인증, 중립적 알림 문구 |

---

## 2. 사용자 스토리 (User Story)

### F-01. 위험 관계 자가진단

> As a **위험한 관계에 처해 있을 수 있는 사용자**,
> I want **체크리스트를 통해 내 관계의 위험 신호를 점검하고 싶다**,
> So that **내 상황이 얼마나 위험한지 객관적으로 파악하고 다음 행동을 결정할 수 있다**.

---

### F-02. 위험 대화 감지

> As a **상대방으로부터 위협적인 메시지를 받은 사용자**,
> I want **대화 내용을 앱에 붙여넣거나 클립보드에서 불러와 위험 여부를 분석하고 싶다**,
> So that **내가 받은 메시지가 위험한 표현인지 즉시 확인하고 대응할 수 있다**.

---

### F-03. 백그라운드 감지 + 배너 알림

> As a **앱을 평소에 백그라운드로 유지하는 사용자**,
> I want **위험 감지 시 눈에 띄지 않는 중립적 배너 알림을 받고 싶다**,
> So that **앱 사용 사실을 노출하지 않으면서도 위험 상황에 즉각 대응할 수 있다**.

---

### F-04. 대응 가이드

> As a **위험 감지 알림을 받은 사용자**,
> I want **지금 당장 내가 할 수 있는 행동을 단계별로 안내받고 싶다**,
> So that **당황하지 않고 즉각적이고 안전한 행동을 취할 수 있다**.

---

### F-05. 맞춤 지원 매칭

> As a **도움을 받고 싶지만 어디에 연락해야 할지 모르는 사용자**,
> I want **내 상황과 위험 유형에 맞는 상담 기관과 복지 제도를 추천받고 싶다**,
> So that **막막함 없이 적합한 지원 경로를 빠르게 찾을 수 있다**.

---

### F-06. 신청 동행

> As a **지원 제도를 신청하고 싶지만 절차를 모르는 사용자**,
> I want **필요한 서류, 신청 방법, 절차 순서를 앱 안에서 안내받고 싶다**,
> So that **혼자서도 지원 신청을 끝까지 완료할 수 있다**.

---

### F-07. 긴급 도움 요청

> As a **즉각적인 위험 상황에 처한 사용자**,
> I want **버튼 하나로 공공기관에 전화하거나 지인에게 문자를 보내고 싶다**,
> So that **빠르게 도움을 요청하고 위험에서 벗어날 수 있다**.

---

### F-08. 상황 기록·조회

> As a **반복적인 위험 상황을 겪고 있는 사용자**,
> I want **위험 상황과 감지 기록을 내 기기에 저장하고 나중에 다시 볼 수 있으면 좋겠다**,
> So that **상황의 흐름을 파악하고 필요 시 증거 자료로 활용할 수 있다**.

---

### F-09. 보안 기능

> As a **앱 사용 사실이 노출되면 위험할 수 있는 사용자**,
> I want **앱에 비밀번호 또는 생체인증을 설정하고, 알림 문구도 외부에서 알아볼 수 없게 하고 싶다**,
> So that **누군가 내 기기를 보더라도 앱의 존재와 사용 목적을 알아차리지 못한다**.

---

## 3. 승인 기준 (Acceptance Criteria)

> 모든 승인 기준은 EARS 문법을 준수합니다.
> AI가 테스트 케이스를 도출할 수 있을 만큼 구체적인 조건과 결과를 정의합니다.

---

### F-01. 위험 관계 자가진단

**3.1 체크리스트 진입**
- WHEN 사용자가 자가진단 메뉴를 탭하면,
- THE SYSTEM SHALL 10개 이상의 위험 신호 항목을 체크리스트 형태로 표시해야 한다.

**3.2 결과 분류**
- WHEN 사용자가 체크리스트를 완료하고 결과 보기를 요청하면,
- THE SYSTEM SHALL 선택 항목 수와 가중치에 따라 **주의 / 경고 / 긴급** 중 하나의 위험도를 도출하여 표시해야 한다.

**3.3 결과 후속 연결**
- WHEN 진단 결과가 경고 또는 긴급으로 분류되면,
- THE SYSTEM SHALL 해당 위험도에 맞는 대응 가이드(F-04) 또는 맞춤 지원 매칭(F-05) 화면으로 이동하는 버튼을 함께 표시해야 한다.

**3.4 기록 저장**
- WHEN 자가진단이 완료되면,
- THE SYSTEM SHALL 진단 일시와 위험도 결과를 로컬 기기에 저장해야 한다 (원문 체크 항목 내용은 저장하지 않는다).

---

### F-02. 위험 대화 감지

**3.5 텍스트 직접 입력**
- WHEN 사용자가 텍스트 입력창에 대화 내용을 붙여넣고 분석 버튼을 탭하면,
- THE SYSTEM SHALL 해당 텍스트를 Python 위험 감지 API로 전송하고 분석 결과를 반환해야 한다.

**3.6 클립보드 자동 불러오기**
- WHEN 사용자가 클립보드 버튼을 탭하면,
- THE SYSTEM SHALL 현재 클립보드에 저장된 텍스트를 입력창에 자동으로 붙여넣어야 한다.

**3.7 위험 문장 강조 표시**
- WHEN 분석 결과가 반환되면,
- THE SYSTEM SHALL 위험으로 탐지된 문장 또는 키워드를 위험도별 색상(주의: 노랑 / 경고: 주황 / 긴급: 빨강)으로 강조 표시해야 한다.

**3.8 위험도 없음 처리**
- WHEN 분석 결과 위험 표현이 탐지되지 않으면,
- THE SYSTEM SHALL "위험한 표현이 감지되지 않았습니다"라는 안내 문구를 표시해야 한다.

**3.9 분석 후 텍스트 보관**
- WHEN 분석이 완료되면,
- THE SYSTEM SHALL 입력된 원문 텍스트를 서버에 전송하거나 앱 내에 영구 저장하지 않아야 한다 (세션 내 임시 표시만 허용).

---

### F-03. 백그라운드 감지 + 배너 알림

**3.10 배너 알림 문구**
- WHEN 위험이 감지되어 알림을 발송할 때,
- THE SYSTEM SHALL 알림 제목과 본문에 앱 이름, 위험 관련 단어, 상담·지원 관련 표현을 포함하지 않는 중립적 문구를 사용해야 한다.

**3.11 단계별 알림 구분**
- WHEN 감지된 위험도가 주의 수준이면,
- THE SYSTEM SHALL 소리 없이 상태바 아이콘만 표시하는 무음 배너 알림을 발송해야 한다.
- WHEN 감지된 위험도가 경고 수준이면,
- THE SYSTEM SHALL 짧은 진동과 함께 배너 알림을 발송해야 한다.
- WHEN 감지된 위험도가 긴급 수준이면,
- THE SYSTEM SHALL 진동 및 알림음과 함께 배너 알림을 발송하고, 알림 탭 시 즉시 긴급 도움 요청 화면(F-07)으로 이동해야 한다.

**3.12 알림 탭 연결**
- WHEN 사용자가 주의 또는 경고 알림을 탭하면,
- THE SYSTEM SHALL 앱의 대응 가이드 화면(F-04)으로 이동해야 한다.

---

### F-04. 대응 가이드

**3.13 가이드 표시**
- WHEN 사용자가 대응 가이드 화면에 진입하면,
- THE SYSTEM SHALL 현재 위험도에 맞는 행동 지침을 우선순위 순서로 표시해야 한다.

**3.14 긴급 연결 버튼 포함**
- WHEN 대응 가이드 화면에서 위험도가 긴급인 경우,
- THE SYSTEM SHALL 화면 상단에 긴급 도움 요청(F-07) 버튼을 고정 표시해야 한다.

**3.15 지원 매칭 연결**
- WHEN 사용자가 대응 가이드 내 '도움 받기' 버튼을 탭하면,
- THE SYSTEM SHALL 맞춤 지원 매칭 화면(F-05)으로 이동해야 한다.

---

### F-05. 맞춤 지원 매칭

**3.16 유형별 추천**
- WHEN 사용자가 자신의 위험 유형(가정폭력 / 데이트폭력 / 스토킹 / 기타)을 선택하면,
- THE SYSTEM SHALL 팀 직접 구축 JSON DB에서 해당 유형에 매칭되는 상담 기관 및 복지 제도 목록을 표시해야 한다.

**3.17 기관 정보 표시**
- WHEN 추천 기관 목록이 표시되면,
- THE SYSTEM SHALL 각 기관의 이름, 전화번호, 운영 시간, 지원 대상을 포함하여 표시해야 한다.

**3.18 전화 연결**
- WHEN 사용자가 기관의 전화번호를 탭하면,
- THE SYSTEM SHALL 해당 번호로 전화 앱을 실행해야 한다.

**3.19 신청 동행 연결**
- WHEN 사용자가 특정 기관 또는 제도의 '신청 방법 보기'를 탭하면,
- THE SYSTEM SHALL 해당 기관의 신청 동행 화면(F-06)으로 이동해야 한다.

---

### F-06. 신청 동행

**3.20 절차 안내 표시**
- WHEN 사용자가 특정 지원 제도의 신청 동행 화면에 진입하면,
- THE SYSTEM SHALL 신청 절차를 단계별 순서(1단계, 2단계…)로 표시해야 한다.

**3.21 필요 서류 안내**
- WHEN 신청 동행 화면이 표시되면,
- THE SYSTEM SHALL 해당 제도 신청에 필요한 서류 목록을 함께 표시해야 한다.

**3.22 단계별 완료 체크**
- WHEN 사용자가 각 절차 단계를 완료로 표시하면,
- THE SYSTEM SHALL 해당 단계를 완료 상태로 표시하고 다음 단계를 강조 표시해야 한다.

---

### F-07. 긴급 도움 요청

**3.23 공공기관 전화 연결 (필수)**
- WHEN 사용자가 긴급 도움 요청 화면에서 공공기관 전화 버튼을 탭하면,
- THE SYSTEM SHALL 여성긴급전화(1366) 또는 경찰(112) 중 사용자가 선택한 번호로 즉시 전화 앱을 실행해야 한다.

**3.24 지인 문자 발송 (선택)**
- WHEN 사용자가 긴급 도움 요청 화면에서 지인 문자 버튼을 탭하면,
- THE SYSTEM SHALL 사전에 등록된 지인 연락처로 미리 설정된 문자 내용을 문자 앱을 통해 전송 준비 상태로 실행해야 한다.

**3.25 지인 연락처 사전 등록**
- WHEN 사용자가 설정에서 긴급 연락처를 입력하고 저장하면,
- THE SYSTEM SHALL 해당 연락처를 로컬에 암호화하여 저장해야 한다.

**3.26 미등록 상태 안내**
- IF 긴급 연락처가 등록되지 않은 상태에서 사용자가 지인 문자 버튼을 탭하면,
- THEN THE SYSTEM SHALL 연락처 등록 화면으로 이동하는 안내 팝업을 표시해야 한다.

**3.27 빠른 접근**
- WHEN 위험도 긴급 알림 또는 대응 가이드에서 긴급 도움 버튼을 탭하면,
- THE SYSTEM SHALL 중간 화면 없이 즉시 긴급 도움 요청 화면으로 이동해야 한다.

---

### F-08. 상황 기록·조회

**3.28 메모 저장**
- WHEN 사용자가 상황 기록 화면에서 메모를 작성하고 저장 버튼을 탭하면,
- THE SYSTEM SHALL 작성 일시와 함께 해당 메모를 로컬 기기에 저장해야 한다.

**3.29 감지 기록 자동 저장**
- WHEN 위험 대화 감지(F-02) 또는 자가진단(F-01)이 완료되면,
- THE SYSTEM SHALL 감지 일시, 위험도, 감지 유형을 기록으로 자동 저장해야 한다 (원문 텍스트는 저장하지 않는다).

**3.30 기록 목록 조회**
- WHEN 사용자가 기록 조회 화면에 진입하면,
- THE SYSTEM SHALL 저장된 기록을 최신순으로 정렬하여 목록으로 표시해야 한다.

**3.31 기록 삭제**
- WHEN 사용자가 특정 기록의 삭제 버튼을 탭하면,
- THE SYSTEM SHALL 확인 팝업 없이 즉시 해당 기록을 로컬에서 삭제해야 한다.

---

### F-09. 보안 기능

**3.32 앱 잠금 설정**
- WHEN 사용자가 설정에서 비밀번호 잠금을 활성화하면,
- THE SYSTEM SHALL 앱 재실행 또는 백그라운드 복귀 시 비밀번호 입력 화면을 표시해야 한다.

**3.33 생체인증 지원**
- WHEN 사용자가 설정에서 생체인증을 활성화하고 기기가 생체인증을 지원하는 경우,
- THE SYSTEM SHALL 앱 잠금 해제 시 비밀번호 대신 지문 또는 얼굴 인증을 제공해야 한다.

**3.34 비밀번호 오류 제한**
- WHEN 사용자가 비밀번호를 5회 연속 오류 입력하면,
- THE SYSTEM SHALL 30초간 추가 입력을 차단하고 대기 시간을 화면에 표시해야 한다.

**3.35 중립적 알림 문구**
- WHEN 시스템이 사용자에게 푸시 알림을 발송할 때,
- THE SYSTEM SHALL 알림 제목과 본문에 '위험', '폭력', '상담', 'Safelink' 등 앱의 목적을 유추할 수 있는 단어를 포함하지 않아야 한다.

**3.36 앱 아이콘 중립화**
- While 앱이 설치된 동안,
- THE SYSTEM SHALL 외부에서 앱의 목적을 유추할 수 없는 중립적인 앱 이름과 아이콘을 표시해야 한다.

**3.37 최소 수집 원칙**
- While 앱이 동작하는 동안,
- THE SYSTEM SHALL 위험 감지 분석 목적으로 전송된 텍스트를 서버에 저장하지 않아야 하며, 분석 완료 즉시 서버 메모리에서 제거해야 한다.
