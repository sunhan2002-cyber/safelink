## 4. keyword.json 확장 결과 (요청 2·3번: keyword 확장 + regex 보강)

- 키워드 항목: **80 → 116개** (+36)
- combo_bonus_rules: **6 → 11개** (+5 — `COMBO-VP-VERIFY-TRANSFER`, `COMBO-RS-GROOMING-MIGRATE`,
  `COMBO-RS-SUNKCOST-INVEST`, `COMBO-GL-DENY-BLAME`, `COMBO-GL-ISOLATION-DISCREDIT`)
- regex-simple 신규 1건 추가: `GL-3-2-006` — "내가 언제 ~했어" 부정/기억불신 패턴을
  문구 변형에 대응하도록 일반화 (`내가\s?언제.{0,15}(했어|그랬어|말했어|라고\s?했어)`)

### combo_bonus_rules를 늘려도 엔진 코드는 안 늘어나게 리팩터링

기존 코드는 `related_subcategory_ids` 기반 콤보 2개를 각각 `if` 문으로 하드코딩하고
있었는데, 5개를 더 하드코딩하는 대신 **"related_subcategory_ids가 있는 specific 콤보는
keyword.json을 순회하며 전부 매칭됐는지 자동 판정"**하도록 `DetectionEngine.evaluateComboRules()`를
일반화했습니다. 앞으로 이 형태의 콤보가 더 늘어도 코드 수정 없이 데이터만 추가하면 됩니다.
(`COMBO-VP-PHONE-VERIFY`/`COMBO-VP-SMISHING`은 "OR 조건"이라 성격이 달라 기존대로 하드코딩 유지.)

## 5. 엔진 개선: 겹치는 매칭 중 긴 것만 점수 반영

지난 04번 문서에서 제안만 하고 보류했던 규칙을 이번에 실제로 구현했습니다
(`DetectionEngine.findSuppressedByOverlap()`). 계기: `GL-3-2-006` regex를 추가했더니
기존 `GL-3-2-001`("내가 언제 그렇게 말했어")과 겹쳐서 **기존 41개 케이스 중 2건이 새로
깨짐**(`TC-GL-POS-02`: 12→18점, `TC-GL-EDGE-01`: 60→66점) — 이게 오히려 이 규칙이 왜
필요한지 실증하는 계기가 됐습니다.

**규칙**: 서로 다른 키워드 id의 매칭 구간이 겹칠 때, 더 짧은(덜 구체적인) 쪽은 점수
계산에서 제외합니다. 단, `matchedKeywords` 목록에는 그대로 남겨서 화면에는 계속
표시되게 했습니다(표시와 점수 반영 분리).

**효과**: 04번 문서에서 발견한 부분 문자열 충돌 2건 중 실제 테스트에 영향을 주던
`VP-1-4-003`/`RS-2-5-001` 건과, 이번에 새로 만든 `GL-3-2-006`/`GL-3-2-001` 겹침이
전부 해결됨.

## 7. 남은 갭 8건 — 왜 아직도 안 잡히는지

전부 "이미 만든 중분류의 다른 표현 변형"이라 키워드를 더 추가하면 잡을 수는 있지만,
**패러프레이즈는 구조적으로 끝이 없다는 걸 보여주는 사례**라 일부러 더 안 채우고
남겨뒀습니다 (예: SMALL_ASK 관련 "100만원만요"는 "기프트카드 번호만"과 표현이 달라서
안 잡힘, INTERMIT 관련 "3주만에 100이 137 됐죠?"는 숫자 기반이라 키워드 매칭 자체가
안 맞는 유형). 6장 참고 — 이게 바로 다음 장의 AI 호출 조건 근거입니다.

## 8. AI API 보조 분석 조건 초안 (요청 6번)

`data/API 입출력 초안 v1`의 기존 조건(회색지대 20~40/55~70, 가스라이팅 3-1·3-2
반복 시 점수 무관 호출)에 **추가로 제안**하는 조건입니다. 기존 문서를 직접 고치지
않고 여기 초안으로만 정리했습니다 — 팀 검토 후 반영 필요.

### 8-1. 신규 가스라이팅 중분류도 "반복 시 점수 무관 호출" 예외에 포함

기존 예외가 3-1(감정무효화)·3-2(현실왜곡)에만 있었는데, 이번에 추가한 **3-7(책임전가)·
3-8(주변인신뢰훼손)·3-9(간헐적보상)도 동일한 이유(어조·맥락 의존적이라 키워드 매칭만으론
오탐/누락 위험 큼)로 이 예외에 포함**시킬 것을 제안합니다.

### 8-2. FUTURE_FAKE(2-8)·SUNK_COST(2-10) 감지 시 세션 길이 기준 추가 호출

이 두 기법은 **단일 문장이 아니라 장기 서사 흐름 안에서만 의미**를 가집니다
("포기하면 원금까지 묶여요"는 그 자체로는 위험 신호인지 판단 불가 — 그 앞에 실제
투자 유도·소액 성공 경험이 쌓여있어야 위험). 제안: 이 두 중분류가 매칭되고 **세션
누적 턴 수가 15턴 이상**이면(장기 관계 구축 후 전환 정황), 회색지대 점수 여부와
무관하게 AI 호출.

### 8-3. score=0인데 사용자가 수동으로 "위험한 것 같다" 표시한 경우

갭 분석에서 확인했듯, 확장 후에도 21%는 키워드로 못 잡습니다(패러프레이즈 다양성은
근본적으로 키워드 매칭의 한계 — 100% 커버리지가 목표가 될 수 없음). 매칭이 0건이라
자동으로는 절대 회색지대에 안 걸리는 경우를 위해, **사용자가 직접 "위험한 것 같다"고
표시하면 점수·매칭과 무관하게 AI 호출**하는 수동 트리거를 제안합니다.

### 8-4. 신규 9개 중분류는 회색지대 폭을 임시로 넓히는 것 제안

신규 중분류는 6개 시나리오만 근거로 설계돼서 아직 실사용 검증이 없습니다. 초기
일정 기간은 이 9개 중분류가 매칭에 관여했을 때만 회색지대를 **20~40/55~70 대신
15~45/60~75로 넓혀서** AI 검증을 더 자주 받게 하고, 실측 데이터가 쌓이면 원래
폭으로 좁히는 걸 제안합니다.

- weight/standalone_recommend 값은 전부 임시값 — 실사용 데이터 쌓이면 튜닝 필요
  (keyword.json `_meta.note`와 동일 원칙)
- 01번 문서의 미해결 이슈(TC-RS-NEG-02 픽스처 오기)는 여전히 그대로
- 이 저장소엔 Android SDK가 없어 `./gradlew test` 실측을 못 했음(이번에도 Android
  의존성 없는 형태로 엔진을 별도 컴파일해서 실행 확인) — 로컬 환경에서 재확인 필요
