> 01·02번 문서가 "동작이 맞는지"(41개 케이스, 샘플 5개)를 봤다면, 이 문서는 **데이터
> 자체가 스스로 앞뒤가 맞는지**를 기계적으로 훑은 결과다. keyword.json 80개 항목 중

- **작업 목적**: 지금까지의 검증(41개 케이스, 샘플 5개)은 "대표 입력이 맞는지"였고,
  keyword.json/institutions.json **데이터 자체의 참조 무결성**과 **80개 키워드 전수
  커버리지**는 아직 확인 안 된 상태였음. 이번 검수로 그 공백을 메움.
- **수정/추가 파일**:
  - `android/app/src/test/java/com/safelink/app/data/repository/DataIntegrityTest.kt` (신규)
  - `android/app/src/test/java/com/safelink/app/data/model/RiskLevelBoundaryTest.kt` (신규)

- **이번 주 목표와 연결되는 이유**: 위험도/키워드/기관 연결에 조용히 숨어있을 수 있는
  참조 누락·죽은 키워드가 없다는 걸 실제로 확인해야 "실제 데이터 기준 흐름"을 믿고
  화면에 노출할 수 있음.

## 2. 검수 결과: 전체 이상 없음 (11개 항목 전부 통과)

### 2-1. 데이터 참조 무결성 (9개 항목)

| 검사 항목 | 결과 |
|---|---|
| `id` 형식(`{VP\|RS\|GL}-N-N-NNN`) 준수 (80건 전체) | PASS |
| `keyword.json`의 모든 `subcategory_id`가 `institutions.json`의 `subcategory_to_risk_type`에 존재 | PASS |
| `subcategory_to_risk_type`의 모든 `risk_types`가 `risk_type_priority` 키로 존재 | PASS |
| `risk_type_priority`의 모든 `institution_id`가 `institutions` 목록에 존재 | PASS |
| `keyword_risk_type_additions`의 키(키워드 id)가 `keyword.json`에 실제 존재 | PASS |
| `keyword_risk_type_additions`의 `add_risk_types`가 `risk_type_priority`에 존재 | PASS |
| `weight` 음수 없음 | PASS |
| `institutions` id 중복 없음 | PASS |
| `keyword.json` id 전체 유일성 | PASS |

### 2-2. 키워드 80개 전수 매칭 커버리지

keyword.json의 keyword형 76개 + regex-simple형 4개, 총 **80개 항목 전부가 각자의 대표
샘플 문자열로 실제 매칭됨**을 확인. (참고: 검수 과정에서 처음엔 regex-simple 4개 중
`RS-2-4-004`(금액+요청 조합 패턴, `"500만원 좀 빌려줘."`로 매칭 확인)의 테스트 샘플을
빠뜨렸다가 추가해서 재확인함 — 데이터 자체 문제는 아니었고 검수 스크립트의 누락이었음.)

### 2-3. 위험도 경계값

`RiskLevel.fromScore()` 경계 10건(0/15/16/30/31/65/66/100/150/-5) 전부 의도한 값 반환 확인.
100 초과·음수 입력도 각각 CRITICAL/SAFE로 방어적으로 처리됨 (엔진 자체에는 100 캡이 있어
정상 경로로는 발생하지 않지만, 방어 코드가 실제로 동작하는지 확인).
