# 신기훈 4주차 결과물 04 - 기존 데이터 이슈 심화 검수

> 01번 문서에 "팀 논의 필요"로 남겨뒀던 2건(키워드 부분 문자열 충돌, 테스트 픽스처 불일치)을
> 전수 스캔으로 다시 파봄. 이전엔 41개 케이스를 돌리다가 "우연히 걸린" 사례였는데, 이번엔
> **모든 키워드 쌍 / 모든 픽스처 항목을 기계적으로 훑어서** 더 있는지 확인했다.

## 1. 키워드 부분 문자열 충돌 — 전수 스캔 결과: 2건 (기존에 안 셈)

`keyword.json`의 keyword형 76개 항목 전체를 서로 짝지어 비교(다른 id끼리 한쪽이 다른쪽의
부분 문자열인 경우)한 결과:

| # | 짧은 쪽 (부분 문자열) | 긴 쪽 (포함하는 쪽) | 같은 subcategory? | 영향 |
|---|---|---|---|---|
| 1 | `VP-1-4-003` "오늘 안에" (보이스피싱/1-4, w20) | `RS-2-5-001` "오늘 안에 처리 안되면" (로맨스스캠/2-5, w20) | **다름** | 반복감쇠가 subcategory별로 걸려서 감쇠 없이 20+20=40 중복 계산 (01번 문서에서 이미 발견한 그 건) |
| 2 | `VP-1-5-001` "안전계좌" (보이스피싱/1-5, w30) | `VP-1-5-002` "안전계좌로 이체" (보이스피싱/1-5, w30) | **같음** | 같은 subcategory라 반복감쇠(2번째부터 50%)는 걸림 — 30 + 15 = 45 (겹치는 같은 신호를 1.5배로 계산). 41개 공식 케이스에는 이 조합이 없어서 지금까지 안 걸렸음 |

**2번은 이번에 처음 발견**. "안전계좌로 이체해주세요" 같은 문장 하나에 두 키워드가 동시에
잡혀서, 사실상 같은 위험 신호("안전계좌 유도")를 1.5배로 점수에 반영하게 됨.

## 2. 테스트 픽스처 불일치 — 전수 검증 결과: 1건 (기존에 발견한 것 그대로, 추가 발견 없음)

41개 케이스의 `expected_matched_ids` 총 75개 항목을 각 turn 텍스트와 하나씩 대조한 결과,
**불일치는 `TC-RS-NEG-02` 1건뿐**이었다 (`RS-2-2-003` "결혼하고 싶어요"가 입력 문장
"우리 결혼할까?"에는 실제로 없음). 나머지 74개 항목은 전부 실제 텍스트와 정확히 일치함.

## 3. 원인 분석 및 권고안

### 3-1. 키워드 부분 문자열 충돌 (2건) — 엔진 로직 개선으로 해결 가능

두 건 다 근본 원인은 같다: **서로 다른 키워드의 매칭 구간이 완전히 겹치는데, 지금 엔진은
"짧은 쪽이 긴 쪽 안에 완전히 포함된 경우"를 구분하지 않고 둘 다 개별 신호로 점수에 더한다.**

**권고**: 매칭 후 점수 계산 전에 "겹치는 매칭 중 더 긴(더 구체적인) 것만 점수에 반영" 규칙을
추가. 구체적으로:
- 같은 텍스트 구간에서 서로 다른 keyword id의 매칭 범위가 겹치고, 한쪽 범위가 다른쪽 범위에
  완전히 포함되면, **포함된(짧은) 쪽은 점수 계산에서 제외** (단, `matchedKeywords` 목록에는
  그대로 남겨서 "이 표현도 감지됐다"는 건 화면에서 보이게 유지 — 표시와 점수 반영을 분리)
- 이렇게 하면 문제 1번(`VP-1-4-003`/`RS-2-5-001`)은 20점(RS-2-5-001만 반영)으로,
  문제 2번(`VP-1-5-001`/`VP-1-5-002`)은 30점(VP-1-5-002만 반영)으로 계산됨
- **`TC-RS-POS-05`, `TC-RS-NEG-04`(현재 `@Ignore` 처리된 2건)가 이 규칙을 적용하면 그대로
  통과함** — 즉 이건 데이터를 안 건드리고 엔진 쪽 규칙 추가만으로 해결 가능한 문제였다.

이 규칙 추가는 **점수 계산 방식(weight 합산 로직)에 손을 대는 변경**이라, 신기훈 판단만으로
조용히 바꾸지 않고 먼저 확인받으려 함. 원하시면 바로 구현해서 41개 케이스 재검증까지
진행할 수 있음.

### 3-2. 테스트 픽스처 불일치 (1건) — 데이터 수정 필요, 엔진으로 해결 불가

이건 엔진 로직 문제가 아니라 `data/위험 문장 테스트.json` 자체의 오기로 보인다.
`TC-RS-NEG-02`의 `expected_matched_ids`에서 `RS-2-2-003`을 빼거나, 입력 문장에
"결혼하고 싶어요"를 포함하도록 고치거나 둘 중 하나를 팀에서 정해야 함 — 엔진 쪽에서
고칠 수 있는 성격의 문제가 아님.
