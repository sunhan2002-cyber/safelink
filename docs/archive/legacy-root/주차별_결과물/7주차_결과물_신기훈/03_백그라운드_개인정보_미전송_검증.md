# 신기훈 7주차 결과물 03 - 백그라운드 감지 개인정보 미전송 검증

> 항목 6("백그라운드에서 개인정보 관련한 사항은 안넘어간다고 표기하기")은 담당자가
> 명시 안 돼 있었지만, 원문 전송/저장 원칙(CLAUDE.md 아키텍처 원칙 2)이 신기훈 도메인과
> 겹쳐서 직접 검증하고 코드에 표기함.

---

## 1. 검증 방법

`MessageDetectionService`(백그라운드 감지 진입점) → `BackgroundDetectionState`(결과
보관) → `RiskNotifier`(알림) 경로를 코드 레벨에서 직접 추적했다.

## 2. 결론: 서버로 전송되는 경로 자체가 없음

`MessageDetectionService.onAccessibilityEvent()`는 `DetectionRepository.analyze(text)`만
호출한다 — **`DetectionRepository.escalateToAI()`는 이 경로 어디에서도 호출되지 않는다**
(`grep`으로 `background`/`notification` 패키지 전체 확인, 호출부 없음).

`analyze()`는 온디바이스 전용 함수라 네트워크 호출이 아예 없다. 즉 마스킹(`[전화번호]`/
`[링크]` 치환) 이전에, **애초에 이 텍스트가 밖으로 나갈 경로 자체가 없다** — 마스킹은
`escalateToAI()` 경로(사용자가 직접 분석 화면에서 입력한 텍스트, 회색지대일 때만)에만
적용되는 별개 안전장치이고, 백그라운드 감지는 그 경로를 아예 안 탄다.

## 3. 저장 여부도 확인

`BackgroundDetectionState.update()`는 `result.originalText`(원문 전체)를 저장하지 않고,
`result.matchedKeywords`에서 **매칭된 짧은 구간(`matchedText`)만 최대 5개** 뽑아서
`MutableStateFlow`(메모리, 디스크 미저장)에 보관한다. 앱이 종료되면 사라진다.

## 4. 코드에 표기

`MessageDetectionService.kt` 클래스 KDoc에 위 내용을 명시적으로 추가했다 — 리뷰어/팀원이
이 파일만 봐도 "개인정보가 어디로도 안 나간다"를 바로 확인할 수 있게.

```kotlin
* ── 개인정보: 서버로 전송되지 않음 (7주차 확인) ─────────────────────────────
*   백그라운드 감지 경로는 [DetectionRepository.analyze]만 호출하고
*   [DetectionRepository.escalateToAI]는 호출하지 않는다 — 즉 이 경로로 읽은 화면 텍스트는
*   네트워크로 나갈 방법 자체가 없다(마스킹 이전에 애초에 전송 경로가 없음)...
```

## 5. 남은 확인 필요 사항 (범위 밖, 팀 논의 필요)

- 이건 **현재 구현 기준** 검증이다. 향후 백그라운드 감지 결과도 AI 보조분석으로 확장하게
  되면(회색지대 케이스 등) 이 문서의 전제가 깨지므로, 그 시점에 마스킹 경로를 백그라운드
  쪽에도 반드시 연결해야 함 — 지금은 "구조상 안전"이지 "영구히 안전"은 아님
- `AccessibilityService`가 읽는 화면 텍스트 자체(카카오톡 등)가 OS/기기 로그에 남는지는
  Android 플랫폼 레벨 문제라 앱 코드로 통제 불가 — 이 문서 범위 밖
