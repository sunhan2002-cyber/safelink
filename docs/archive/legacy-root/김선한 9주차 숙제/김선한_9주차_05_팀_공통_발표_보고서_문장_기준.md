# 김선한 9주차 05 팀 공통 발표 보고서 문장 기준

## 목적

- 팀원들이 발표와 보고서에서 서로 다른 표현을 쓰지 않도록 공통 설명 문장을 한 파일에 모은다.

## 프로젝트 구조 설명

- "SafeLink는 1차 규칙 기반 분석과 2차 AI 보조분석을 결합한 하이브리드 구조를 사용합니다."
- "1차 분석은 기기 내에서 수행되며, 키워드, 문장 규칙, 상황 규칙을 함께 반영합니다."
- "2차 AI 보조분석은 1차 분석이 애매한 경우에만 보완적으로 사용됩니다."

## 현재 단계 설명

- "현재 SafeLink는 시연 가능한 핵심 분석 흐름을 구현한 단계입니다."
- "텍스트 입력, 스크린샷 분석, 백그라운드 감지까지 이어지는 기본 흐름을 확인할 수 있습니다."
- "정확도와 감지 범위는 계속 확장 중입니다."

## 한계 설명

- "현재 구조는 단순 키워드 매칭을 넘어서 문장 규칙과 상황 규칙까지 반영하지만, 모든 표현 변형과 긴 문맥을 완벽히 이해하는 단계는 아닙니다."
- "사용자 화면에서는 아직 분석 결과가 키워드 중심처럼 보일 수 있다는 한계가 있습니다."
- "백그라운드 감지는 현재 일부 대상 앱 중심으로 검증 중이며, 범위 확장은 진행 중입니다."

## 차별점 설명

- "SafeLink는 위험 신호를 감지하는 데서 끝나지 않고, 대응 가이드와 지원 기관 연결까지 이어지는 피해 예방형 구조를 지향합니다."
- "또한 원문을 무조건 외부로 보내는 방식이 아니라, 1차 온디바이스 분석 후 필요한 경우에만 AI 보조분석을 사용한다는 점이 차별점입니다."

## 개선 방향 설명

- "향후에는 문장 규칙과 상황 규칙의 패턴 수를 늘리고, 더 다양한 실제 유사 대화 사례로 검증 범위를 넓힐 계획입니다."
- "AI 보조분석은 1차 분석을 대체하는 것이 아니라 회색지대 판단을 보완하는 방향으로 안정화할 예정입니다."
- "감지 대상 앱 범위와 결과 화면 설명력도 함께 확장할 계획입니다."

## 발표에서 피해야 할 표현

- "우리 앱은 모든 대화를 완벽하게 이해합니다."
- "AI가 전체 판단을 전부 대신합니다."
- "모든 메신저를 완벽하게 감지합니다."

## 최종 점검

- 교수님 질문 대응용 설명 가능
- 심사자용 구조 설명 가능
- 팀원 공통 발표 문장 확보
- 보고서 본문용 문장 초안 확보
