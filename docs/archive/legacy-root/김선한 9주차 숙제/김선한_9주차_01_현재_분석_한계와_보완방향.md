# 김선한 9주차 01 현재 분석 한계와 보완 방향

## 목적

- 영상 시연, 발표, 보고서에서 현재 분석 구조를 왜 이렇게 설계했는지 설명할 수 있도록 기준 문장을 정리한다.
- 현재 앱의 한계를 숨기지 않고, 어디까지 완료되었고 무엇을 보완 중인지 팀 기준으로 통일한다.

## 현재 분석 구조 요약

- 1차 분석: 온디바이스 규칙 기반 분석
- 2차 분석: AI API 보조 분석
- 입력 경로: 텍스트 입력 / 스크린샷 OCR / 백그라운드 감지

## 현재 강점

- 앱 내부에서 바로 위험도 계산이 가능하다.
- 키워드, 문장 규칙, 상황 규칙을 함께 반영하는 구조를 갖추고 있다.
- AI API가 실패해도 기본 분석 흐름은 유지된다.
- 스크린샷 분석, 백그라운드 감지, 결과 화면, 대응 가이드까지 실제 시연 가능한 흐름이 있다.

## 현재 한계

### 1. 사용자 입장에서 아직 키워드 중심처럼 보일 수 있음

- 내부적으로는 문장 규칙, 상황 규칙, AI 보조분석이 들어가더라도
  사용자 화면에서는 여전히 매칭 키워드가 가장 먼저 눈에 들어온다.
- 따라서 시연 시에는 "키워드만 보는 앱"처럼 오해받을 가능성이 있다.

### 2. 문장/상황 규칙의 범위가 아직 충분히 넓지 않음

- 일부 표현 변형, 완곡한 말투, 긴 맥락형 대화는 아직 놓칠 수 있다.
- 즉 현재 구조는 완성형 의미 이해 엔진이 아니라, 확장 가능한 규칙 기반 분석기라고 보는 것이 정확하다.

### 3. AI 보조분석은 보완 수단이지 메인 분석기가 아님

- 현재 구조에서 AI는 회색지대 판단, 추가 보정, 문맥 보완 역할이다.
- 따라서 "모든 위험 대화를 AI가 이해한다"라고 설명하면 과장이다.

### 4. 백그라운드 감지 범위는 아직 제한적임

- 현재 검증 기준은 접근성 기반 감지 구조와 카카오톡 중심 시연 흐름이다.
- 기획 의도상 더 넓은 범위 확장은 가능하지만, 현재는 확장 중 기능으로 설명하는 것이 맞다.

## 보완 방향

### 단기 보완

- 결과 화면에서 문장 규칙, 상황 규칙, AI 보조분석 근거를 더 자연스럽게 보이도록 다듬기
- 위험도 설명 문구를 키워드 중심 표현에서 규칙 기반 설명으로 보강하기
- OCR 실패, 무텍스트, 짧은 텍스트 예외 처리를 더 명확하게 안내하기

### 중기 보완

- 문장 규칙과 상황 규칙의 패턴 수를 늘리기
- 더 다양한 피싱/로맨스스캠/가스라이팅 대화 샘플로 검증하기
- 감지 대상 앱 범위를 넓히고 백그라운드 감지 안정성을 높이기

### 장기 보완

- 규칙 기반 분석 한계를 줄이기 위해 더 정교한 문맥 판단 구조 검토
- AI 보조분석을 실제 서비스 환경에 맞게 안정화
- 보고서 이후 단계에서 모델/데이터 확장 전략 구체화

## 발표용 핵심 문장

- "SafeLink는 1차적으로 기기 내 규칙 기반 분석을 수행하고, 애매한 경우에만 2차 AI 보조분석을 사용하는 하이브리드 구조입니다."
- "현재 구현은 단순 키워드 매칭을 넘어서 문장 규칙과 상황 규칙까지 반영하지만, 표현 변형과 긴 문맥 대응은 계속 확장 중입니다."
- "즉 지금 단계는 시연 가능한 핵심 분석 구조를 완성한 상태이고, 정확도와 범위는 계속 보완하는 단계입니다."

## 완료 기준 대조

- 현재 분석 한계가 문서로 정리되어 있음
- 키워드 중심처럼 보이는 현재 문제가 팀 기준으로 정리되어 있음
- 보완 방향이 단기, 중기, 장기로 구분되어 있음
- 교수님이나 심사자에게 현재 구조의 이유를 설명할 수 있는 핵심 문장이 포함되어 있음
