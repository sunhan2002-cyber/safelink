# 개발 우선순위표

## 목적

다음 주부터 SafeLink 개발에 바로 들어가기 위해 구현 순서를 정리한다.
우선순위는 단순 중요도가 아니라, 핵심 흐름 완성도와 실제 개발 착수 가능성을 함께 기준으로 잡는다.

## 이번 문서의 해석 기준

이 우선순위표는 `다음 주에 모든 화면을 완성한다`는 뜻이 아니다.

다음 주 목표는 아래와 같이 이해한다.

- 모든 화면 완성 X
- 모든 기능 완성 X
- 핵심 화면 우선 구현 O
- 핵심 사용자 흐름 1개 이상 실제 동작 O

즉, 다음 주는 전체 앱 완성이 아니라 아래 흐름 중 최소 1개를 실제로 동작시키는 것이 목표다.

- `홈 -> 자가진단 -> 자가진단 결과 -> 대응 가이드 또는 지원 연결`
- `홈 -> 분석 입력 -> 분석 결과 -> 대응 가이드 또는 지원 연결`

## 우선순위 기준

- 핵심 사용자 흐름에 직접 필요한가
- 현재 문서/피그마/분석 기준이 이미 정리되어 있는가
- Android와 백엔드가 바로 병렬 작업 가능한가
- 다른 기능의 기반이 되는가
- 데모 구현에 빠르게 연결되는가

## 1순위: 다음 주 바로 시작해야 하는 항목

### 1. 홈 대시보드 화면 구현

- 앱의 메인 진입 화면이자 모든 기능의 허브
- 자가진단, 분석, 기록, 설정으로 분기되는 중심 화면
- 김재겸의 피그마 초안이 이미 있어 화면 구현 착수가 쉬움

### 2. 자가진단 화면 + 자가진단 결과 화면 구현

- SafeLink의 핵심 기능 중 하나
- 서버 연동 없이도 앱 내부 로직으로 먼저 구현 가능
- 빠르게 동작하는 데모를 만들 수 있음

### 3. 스크린샷/텍스트 분석 입력 화면 구현

- 서버 API와 직접 연결되는 핵심 진입 화면
- 분석 기능 시연의 출발점이므로 우선순위가 높음
- 분석 결과 화면과 세트로 봐야 함

### 4. 분석 결과 화면 구현

- `/analyze` API 결과를 실제로 보여줄 화면
- 위험도, 위험 유형, 대응 유도 문구를 보여주는 핵심 출력 화면
- 대응 가이드와 지원 추천 화면으로 연결되는 중심 역할

### 5. `/analyze` API 구현

- SafeLink의 핵심 차별점인 위험 분석 기능
- 신기훈의 위험도 계산 초안, 키워드 코드 초안, 카테고리 초안을 기반으로 바로 구현 가능
- 다음 주 시연 가치가 가장 높은 백엔드 기능

## 2순위: 1순위가 잡히면 바로 이어서 구현할 항목

### 6. 분석 진행 중 화면 구현

- 사용자 경험상 필요
- 분석 요청과 결과 사이의 상태를 자연스럽게 연결
- 피그마 초안에 이미 존재함

### 7. 대응 가이드 화면 구현

- SafeLink의 차별점인 “분석 후 대응” 흐름을 담당
- 결과만 보여주고 끝나지 않게 만드는 핵심 화면

### 8. 지원 서비스 추천 화면 구현

- 지원 연결까지 이어주는 핵심 화면
- 김우영의 데이터 항목/문구 방향과 API 초안을 연결 가능
- `/recommend/institutions` API와 세트로 구현해야 함

### 9. `/recommend/institutions` API 구현

- 분석 결과를 기관 추천으로 이어주는 백엔드 기능
- institutions.json 구조 초안이 정리되면 바로 연결 가능
- 분석 API 다음 단계로 적절함

### 10. 활동 기록 화면 구현

- 자가진단 결과와 분석 결과를 저장/재확인하는 기능
- 앱 내부 저장 구조(SQLite)와 연결하기 좋음
- 1차 구현 범위 안에서 실용성이 높음

## 3순위: 기본 구조가 잡힌 뒤 구현할 항목

### 11. 설정 화면 구현

- 보안/알림/앱 설정 관리용
- 핵심 시연 흐름보다는 보조 기능 성격
- 하지만 앱 완성도를 위해 초반 구조는 잡아두는 것이 좋음

### 12. 앱 잠금 / 생체인증 구조 반영

- 보안 기능으로 중요하지만 핵심 흐름 이후 적용 가능
- 초기에는 설정 화면 구조와 연결만 먼저 잡아도 됨

### 13. 활동 기록 저장 구조(SQLite) 정교화

- 1차에서는 결과 저장만 우선
- 이후 메모, 기록 상세, 재조회 기능까지 확장

### 14. 알림 기능 초안

- 백그라운드 감지와 알림은 중요하지만 구현 난도가 있음
- 1차에서는 분석 결과 기반 안내/배너 문구 위주로 접근

## 최종 정리

다음 주 개발의 최우선 목표는 아래 흐름을 실제로 동작하게 만드는 것이다.

`홈 -> 자가진단 또는 분석 입력 -> 결과 확인 -> 대응 가이드 -> 지원 연결`

즉, 다음 주는 많은 기능을 넓게 만드는 것보다,
핵심 흐름 하나를 실제로 동작하게 만드는 쪽이 우선이다.
