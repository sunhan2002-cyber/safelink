# 팀원 결과물 점검표

## 목적

이번 주 기준으로 팀원들이 제출한 결과물이 실제로 존재하는지, 이번 주 공통 목표와 맞는지, 다음 주 개발에 바로 연결 가능한지를 점검한다.

## 점검 기준

- GitHub에 실제 업로드되었는가
- 이번 주 공통 목표와 연결되는가
- 다음 주 개발에 바로 사용할 수 있는가
- 다른 팀원 결과물과 연결 가능한가
- 빠진 핵심 항목은 없는가

## 이번 주 공통 목표

- 필수 화면 확정
- 화면 흐름 확정
- 위험도 계산 방식 v1 확정
- keywords.json v1 확보
- institutions.json 구조 초안 확보
- API 초안 확보
- 다음 주 바로 개발할 화면/기능 우선순위 확정

- `교수님_질문_답변_정리.md`

- `앱_기능별_역할분담.md`
- 기타 초기 기획 문서

### 점검

- 프로젝트 설명 방향 정리 완료
- 교수님 질문 3가지 답변 정리 완료
- 기술명세서 초안 존재
- 전체 기획/설명 문서 기준 역할 수행 완료
- 이번 주 추가 작업으로 필수 화면 목록, 화면 흐름, API 초안, 우선순위표, 점검표, 회의 취합본 작성이 필요함

### 현재 판단

- 문서 기준 정리 역할은 수행 중
- 이번 주 목표와 맞는 방향
- 최종 취합과 기준 통일 책임이 계속 필요함

### 보완 필요

- 일요일 회의용 취합본 작성
- 팀원 결과물 최종 점검 반영

## 빠진 핵심 항목

현재 기준으로 아직 최종 확정 또는 명시적으로 정리되지 않은 핵심 항목은 아래와 같다.

- `keywords.json v1` 확정본
- `institutions.json` 구조 초안 정리본
- 화면 흐름 최종 도식 또는 확정본
- 일요일 회의용 최종 취합본

## 결과물 연결 관계 점검

### 잘 연결되는 부분

- 신기훈의 위험 분석 초안 -> API 분석 문서 -> 분석 결과 화면
- 김재겸의 피그마 화면 -> 필수 화면 목록 -> 화면 흐름 요약본
- 김우영의 데이터/문구 초안 -> 추천 API -> 추천 화면/설정 화면
- 김선한의 문서 정리 -> 전체 기준 통합 및 역할 정리

### 조율 필요한 부분

- 위험 유형 명칭 통일
- 추천 기관 데이터 구조 통일
- 화면 이름과 문서 이름 통일
- 결과 화면에서 보여줄 문구 형식 통일

## 최종 판단

현재 팀원별 결과물은 `아예 없는 상태`가 아니라, 모두 초안 또는 기초 결과물은 존재한다.

이번 주 핵심은 새로 처음부터 만드는 것보다,

- 기존 결과물을 개발 가능한 형태로 정리하고
- 화면/분석/API/데이터 기준을 서로 맞추고
- 다음 주 실제 구현 흐름으로 연결하는 것

에 있다.

즉, 이번 주 결과물 점검 기준으로는 팀 전체 방향은 맞고, 현재 단계는 `초안 정리 -> 개발 기준 확정` 단계로 판단한다.
