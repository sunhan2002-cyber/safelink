Safelink 1주차 스펙 문서 초안

1. 기능명
- 프로젝트 소개 및 핵심 기능 정의

기능 목적
- Safelink가 어떤 문제를 해결하는 앱인지 명확하게 정리한다.
- 팀원 전체가 같은 방향으로 개발할 수 있도록 기준을 세운다.

사용자
- 팀원 전체
- 발표 준비자
- 기획 및 개발 담당자

입력값
- 공학경진대회 안내서 내용
- 팀 아이디어
- 위험한 관계 관련 시나리오 예시

출력값
- 프로젝트 한줄 소개
- 핵심 기능 목록
- 서비스 차별점 정리

기능 설명
- 팀이 논의한 아이디어를 바탕으로 앱의 목적과 핵심 기능을 문서화한다.
- 이후 모든 개발과 발표 자료는 이 정의를 기준으로 작성한다.

화면 흐름
- 해당 없음

예외 상황
- 팀원마다 앱 방향 이해가 다를 수 있음
- 기능 범위가 너무 넓어질 수 있음

보안 또는 주의사항
- 민감한 관계 문제를 다루므로 기능 설명에서도 사용자 보호 관점을 포함해야 함

완료 조건
- 프로젝트 한줄 소개가 확정되어 있다.
- 핵심 기능이 필수 기능 중심으로 정리되어 있다.
- 팀원 모두가 동일한 서비스 방향을 이해하고 있다.

주간 결과물
- 프로젝트 소개 문서
- 앱 기능 정리 문서
- README 초안 또는 업데이트

2. 기능명
- 팀원 역할 분담 정리

기능 목적
- 각 팀원의 역할을 명확히 나누어 이후 작업 충돌을 줄인다.

사용자
- 김선한
- 김우영
- 김재겸
- 신기훈

입력값
- 팀원 이름
- 각자 맡을 수 있는 작업 영역

출력값
- 역할 분담 문서

기능 설명
- 팀장을 포함한 각 팀원의 담당 분야를 정리하고, 기획, 기술 조사, UI/UX, 문서화 역할을 구분한다.

화면 흐름
- 해당 없음

예외 상황
- 특정 역할에 업무가 과도하게 몰릴 수 있음
- 기술 담당과 문서 담당의 경계가 불명확할 수 있음

보안 또는 주의사항
- 역할은 고정이 아니라 스프린트마다 조정 가능하도록 운영한다.

완료 조건
- 각 팀원의 기본 역할이 정리되어 있다.
- 2주차부터 바로 작업 시작이 가능하다.

주간 결과물
- 1주차 할일 문서
- 역할 분담 초안

3. 기능명
- 기술 리스크 및 대안 정리

기능 목적
- 메신저 백그라운드 감지, 플랫폼 제한, 개인정보 노출 문제를 미리 검토한다.

사용자
- 팀원 전체
- 발표 준비자

입력값
- 백그라운드 감지 아이디어
- Android 및 iOS 제약사항
- 앱 잠금 및 생체인증 요구사항

출력값
- 기술 리스크 메모
- 구현 대안 정리

기능 설명
- 카카오톡 직접 감지 기능의 리스크를 확인하고, Android 데모 우선 방식과 사용자 동의 기반 대안을 정리한다.

화면 흐름
- 해당 없음

예외 상황
- 구현 가능성보다 아이디어가 앞설 수 있음
- 심사에서 기술 완성도 질문이 나올 수 있음

보안 또는 주의사항
- 민감 데이터 최소 수집 원칙
- 알림 문구의 중립성 유지
- 앱 잠금 기능 필요성 반영

완료 조건
- 기술 리스크와 대안이 문서로 정리되어 있다.
- 발표에서 설명 가능한 수준으로 논리가 정리되어 있다.

주간 결과물
- 기술 리스크 정리 문서
- 대안 구현 방향 메모
