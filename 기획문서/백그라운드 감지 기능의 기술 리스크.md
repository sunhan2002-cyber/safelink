# 백그라운드 감지 기술 조사 및 개발 방향

# 개요

Safelink는 위험한 관계 속에서 나타나는 언어적·정서적 위험 신호를 빠르게 감지하고, 사용자가 안전하게 도움을 받을 수 있도록 지원하는 보호형 지원 앱 프로젝트이다.

본 문서는:

- Android 기반 백그라운드 감지 가능 여부
- 실제 구현 가능한 범위
- 기술 리스크
- 현실적인 개발 방향

을 정리하기 위한 목적을 가진다.

---

# 기술 조사 목적

Safelink의 핵심 아이디어 중 하나는:

```text
위험 표현 및 통제적 언어를 빠르게 감지하는 기능
```

이다.

이를 위해:

- Android 백그라운드 실행 구조
- 메신저 알림 감지 가능 여부
- 현재 화면 분석 가능 여부
- 실시간 위험 감지 구조

를 조사하였다.

---

# 1. Foreground Service 기반 실행

## 개념

Android는 일반 Background Service 실행을 제한하지만:

```text
Foreground Service
```

는 사용자에게 알림(Notification)을 표시하는 조건으로 지속 실행 가능하다.

즉:

```text
앱 실행 중 알림 표시
+
백그라운드 수준 실행 유지
```

구조가 가능하다.

---

## 구조

```text
Safelink 보호 모드 ON
→ Foreground Service 실행
→ 상태바에 “Safelink 실행 중” 표시
→ 감지 기능 유지
```

---

## 가능한 기능

- 앱 지속 실행 유지
- 실시간 이벤트 감지 유지
- Notification Listener 연동
- Accessibility Service 연동

---

## 장점

- Android 기반 지속 실행 가능
- 감지 기능 유지 가능
- 실시간 구조 구현 가능

---

## 단점

- 상태바 알림 지속 노출
- 배터리 사용 증가 가능
- 장시간 실행 부담 존재

---

# 2. Notification Listener 기반 감지

## 개념

Android의:

```text
NotificationListenerService
```

를 활용하면 사용자가 허용한 알림(Notification)의 일부 텍스트를 감지할 수 있다.

---

## 구조

```text
카카오톡 알림 도착
→ Notification Listener 감지
→ 알림 텍스트 분석
→ 위험 키워드 탐지
```

---

## 가능한 기능

- 새 메시지 알림 감지
- 특정 키워드 분석
- 위험 표현 탐지
- 자체 경고 알림 생성

---

## 가능한 수준

예시:

```text
"왜 연락 안 받아?"
"당장 전화해"
"무시하지 마"
```

같은 표현 감지 가능성 존재

---

## 한계

- 알림에 표시된 텍스트만 가능
- 전체 채팅방 접근 불가
- 이전 대화 접근 어려움
- 알림 숨김 설정 시 분석 불가

---

# 3. Accessibility Service 기반 화면 분석

## 개념

Accessibility Service를 활용하면 현재 화면의 UI 요소 및 텍스트를 읽을 수 있다.

즉:

```text
현재 사용자가 보고 있는 화면
```

기준 분석 가능성 존재

---

## 구조

```text
사용자가 카카오톡 채팅방 사용
→ Accessibility Service가 화면 변화 감지
→ 현재 화면 텍스트 읽기
→ 위험 키워드 분석
```

---

## 가능한 기능

- 현재 화면 텍스트 읽기
- UI 변화 감지
- 위험 표현 분석
- 실시간 화면 기반 감지

---

## 가능한 수준

현재 사용자가 보고 있는 채팅방 화면 기준 분석 가능성 존재

---

## 한계

- 현재 화면 기준
- 전체 대화 자동 수집 어려움
- 스크롤 외 영역 접근 제한
- 앱 구조 변경 영향 가능성 존재

---

# 4. MediaProjection + OCR 기반 분석

## 개념

MediaProjection을 활용해 화면을 캡처하고 OCR로 텍스트를 추출하는 방식

---

## 구조

```text
화면 캡처
→ OCR 처리
→ 텍스트 추출
→ 위험 키워드 분석
```

---

## 가능한 기능

- 화면 전체 분석 가능성
- 텍스트 노드 접근 어려운 경우 활용 가능

---

## 장점

- 화면 기반 전체 분석 가능성
- OCR 기반 확장 가능

---

## 단점

- OCR 정확도 문제
- 실시간 처리 부담 증가
- 성능 부담 큼

---

# 기술 리스크

# 1. 메신저 전체 데이터 접근 어려움

현재 일반 앱이:

- 카카오톡 내부 DB
- 전체 채팅 기록
- 과거 메시지

를 자유롭게 읽는 것은 어렵다.

---

## 어려운 기능

- 전체 대화 자동 수집
- 삭제 메시지 복구
- 메신저 내부 저장 데이터 접근
- 모든 메신저 완벽 지원

---

# 2. Android 버전별 제한 차이

Android 버전에 따라:

- 백그라운드 정책
- Foreground Service 제한
- 권한 구조

가 달라질 수 있다.

특히 Android 14 이상은:

```text
Foreground Service 타입 선언
```

이 요구된다.

---

# 3. 메신저 앱별 구조 차이

앱마다:

- 알림 구조
- UI 구조
- 텍스트 표시 방식

이 다르기 때문에 동일한 방식으로 완벽 지원이 어렵다.

---

# 4. 성능 및 배터리 문제

실시간 감지는:

- 배터리 사용 증가
- 메모리 점유 증가
- 장시간 실행 부담

이 발생할 수 있다.

---

# 현실적인 개발 방향

# 1차 핵심 기능

가장 안정적으로 구현 가능한 기능 우선 개발

---

## 추천 구조

```text
사용자 직접 입력/복사 붙여넣기
→ 위험 키워드 및 패턴 분석
→ 위험도 표시
→ 대응 가이드 제공
→ 상담기관 및 지원 연결
→ 앱 잠금/생체인증
```

---

## 장점

- 구현 안정성 높음
- 플랫폼 영향 적음
- 테스트 및 시연 용이

---

# 2차 확장 기능

Android 기반 실험 감지 기능 추가 검토

---

## 추천 구조

```text
보호 모드 ON
→ Foreground Service 실행
→ Notification Listener 활성화
→ Accessibility Service 연동
→ 현재 화면/알림 분석
→ 위험 신호 감지
```

---

# 최종 개발 방향

Safelink는:

```text
“사용자 보호 모드를 기반으로
위험 신호를 분석하고 대응 행동까지 연결하는
Android 중심 보호 지원 앱”
```

방향으로 개발한다.

---

# 핵심 개발 우선순위

## 1순위

- 직접 입력 분석
- 위험도 분석
- 대응 가이드
- 보안 기능

---

## 2순위

- Foreground Service
- Notification Listener
- Accessibility 기반 감지 실험

---

# 최종 목표

```text
실제로 구현 가능한 범위를 기준으로
공학경진대회 수준의 안정적인 데모 완성
```
