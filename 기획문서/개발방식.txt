Safelink 개발 방식

개발 방식 개요
- Safelink는 애자일 방식과 스펙 주도 개발 방식을 함께 사용한다.
- 매주 결과물을 만드는 애자일 방식으로 진행하되, 구현 전에 기능 스펙을 먼저 정리한 뒤 AI와 협업하여 개발한다.
- 목표는 빠르게 만들기만 하는 것이 아니라, 문서와 코드가 함께 남는 체계적인 협업 개발이다.

핵심 원칙
1. 매주 결과물을 남긴다.
- 매주 문서, 화면, 기능, 데모 중 최소 1개 이상의 확인 가능한 결과물을 만든다.

2. 만들기 전에 스펙을 먼저 작성한다.
- 구현 전에 기능 목적, 입력, 출력, 흐름, 예외 상황, 완료 조건을 먼저 정리한다.

3. AI는 스펙을 기준으로 활용한다.
- AI에게 막연히 만들어 달라고 하기보다, 정리된 스펙을 기반으로 코드 초안, 문서 초안, 테스트 시나리오를 요청한다.

4. 팀원 검토를 반드시 거친다.
- AI가 만든 결과물은 그대로 사용하지 않고, 팀원들이 기능 적합성과 발표 적합성을 검토한 뒤 수정한다.

5. 작은 단위로 완성한다.
- 큰 기능을 한 번에 끝내려고 하지 않고, 1주 안에 끝낼 수 있는 크기로 나누어 구현한다.

주간 작업 흐름
1. 이번 주 목표 정하기
- 이번 주에 끝낼 기능 1~2개를 선정한다.

2. 스펙 작성하기
- 기능 스펙 문서를 짧게라도 먼저 작성한다.

3. AI와 협업하기
- 스펙을 기반으로 화면 구조, 코드 초안, API 구조, 문구, 테스트 시나리오를 생성한다.

4. 팀원 역할별 작업 진행
- Java 담당은 앱 화면과 안드로이드 기능 구현
- Python 담당은 분석 로직과 백엔드 구현
- UI/UX 담당은 화면 흐름과 문구 보완
- 문서 담당은 스펙, 결과 정리, 발표 자료 초안 작성

5. 주간 결과물 점검
- 주차 종료 시 데모, 문서, 화면, 기능 중 완성된 결과를 확인한다.

6. 다음 주 목표 조정
- 이번 주 진행 상황을 바탕으로 다음 주 목표를 수정하거나 세분화한다.

AI와 협업하는 방식
- 기능 설명이 아닌 기능 스펙을 기반으로 요청한다.
- 화면 구현 전에는 와이어프레임과 사용자 흐름을 먼저 설명한다.
- 백엔드 구현 전에는 입력값, 출력값, 데이터 구조를 먼저 정의한다.
- 문서 작성 시에는 결과 보고서, 발표 자료, README까지 함께 정리한다.

AI에게 요청할 수 있는 작업 예시
- Java 안드로이드 화면 코드 초안 작성
- Python 위험 분석 API 구조 설계
- 배너 알림 문구 초안 작성
- 기능 테스트 시나리오 작성
- 결과 보고서용 기능 설명 문장 정리

Safelink에 이 방식이 적합한 이유
- 짧은 개발 기간 안에 매주 진행 상황을 확인할 수 있다.
- 문서와 코드가 함께 정리되어 발표 준비가 쉬워진다.
- AI를 보조 도구가 아니라 협업 도구로 활용할 수 있다.
- 팀원별 역할 분담이 명확해지고, 작업 누락을 줄일 수 있다.

최종 목표
- 2026년 8월 28일 제출 전까지 매주 누적된 결과물을 바탕으로
- 시연 가능한 앱 데모
- 결과 보고서
- 작품 안내 팜플렛
- 소개 영상
를 안정적으로 완성한다.
