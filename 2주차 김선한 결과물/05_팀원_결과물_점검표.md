# 팀원 결과물 점검표

## 목적

이번 주 기준으로 팀원들이 올린 결과물을 `실제로 제출했는지`만 보는 것이 아니라, `현재 SafeLink 기획 방향과 맞는지`, `바로 다음 개발 기준으로 쓸 수 있는지`까지 점검한다.

## 점검 기준

- GitHub 또는 별도 링크로 실제 결과물이 확인되는가
- 현재 SafeLink 방향과 맞는가
- 이번 주 공통 목표와 직접 연결되는가
- 다음 주 개발 기준으로 바로 이어질 수 있는가
- 수정이 필요한 어긋난 부분이 있는가

## 현재 SafeLink 기준 방향

- URL 검사 앱이 아니라 `위험한 대화/상황을 감지하고 대응 가이드와 지원 정보를 연결하는 디지털 안전 지원 앱`이다
- 핵심 흐름은 `자가진단 또는 대화 분석 -> 위험도 판단 -> 대응 가이드 -> 기관/지원 연결`이다
- AI는 서비스 전체 중 하나의 분석 수단이며, 앱 전체를 AI 중심으로 설명하지 않는다
- 분석 대상은 대화 텍스트, OCR 추출 텍스트, 위험 표현, 상황 시나리오다

## 이번 주 공통 목표

- 필수 화면 확정
- 화면 흐름 확정
- 위험도 계산 방식 v1 확정
- `keywords.json` v1 확보
- `institutions.json` 구조 초안 확보
- API 초안 확보
- 다음 주 바로 개발할 화면/기능 우선순위 확정

## 김선한

### 확인된 결과물

- `프로젝트_설명문서_초안.md`
- `교수님_질문_답변_정리.md`
- `기술명세서_초안.md`
- `앱_기능별_역할분담.md`
- 이번 주 추가 정리 문서들

### 맞는 것

- 프로젝트 방향을 `위험 대화 감지 + 대응 지원` 기준으로 설명 문서에 반영함
- 교수님 질문 3가지에 맞춰 답변 문서를 정리함
- 전체 문서 기준을 잡는 역할은 현재 가장 맞게 수행됨
- 이번 주 공통 목표를 문서 관점에서 연결하는 역할과 맞음

### 수정 필요한 것

- 기존 문서 중 일부 표현은 너무 일반적인 서비스 소개 문장에 머물러 있어서, 실제 화면/데이터/API 기준과 더 강하게 연결될 필요가 있음

### 빠진 것

- 없음이라기보다, 최종적으로는 팀원 결과물을 한 기준으로 다시 묶는 취합 책임이 계속 남아 있음

### 판단

- 현재 방향과 가장 잘 맞는 축은 김선한 문서들이다
- 이번 주 기준 총괄/검토 역할로 유지하는 게 맞다

## 신기훈

### 확인된 결과물

- `카테고리 초안`
- `위험도 계산 방식 초안`
- `시나리오 초안`
- `시나리오 키워드 코드 초안`
- `docs/Design.md`
- `docs/Requirements.md`
- `docs/Tasks.md`

### 맞는 것

- 위험 유형 분류, 시나리오, 키워드, 위험도 계산은 현재 SafeLink 핵심 로직과 직접 맞음
- 교수님 질문 중 `데이터는 어디서 오는가`, `AI를 어떻게 학습시킬 것인가`와도 자연스럽게 연결됨
- `keywords.json`, 분석 API, 위험도 계산 v1의 기초 자료로 쓰기 좋음

### 수정 필요한 것

- 초안 형태가 많아서 실제 개발 파일 형식으로는 아직 덜 정리됨
- 위험 유형 명칭, 점수 기준, 임계값을 화면/응답 문구와 같은 이름으로 통일해야 함

### 빠진 것

- `keywords.json v1` 실파일
- 점수표 확정본
- API 응답에 들어갈 최종 위험 유형명

### 판단

- 방향은 맞다
- 다만 `좋은 아이디어 초안` 단계에서 `개발 입력값` 단계로 바꾸는 작업이 이번 주 안에 필요하다

## 김재겸

### 확인된 결과물

- `safelink_로드맵.md`
- `safelink_로드맵.txt`
- `safelink_세부일정.txt`
- 피그마 화면 초안 링크

### 피그마에서 확인한 방향

- 스플래시
- 온보딩
- 홈 대시보드
- 분석 진행 중
- 활동 기록
- 지원 서비스 추천
- 대응 가이드

### 맞는 것

- 화면 초안은 실제로 존재하고, 현재 SafeLink 방향과 맞는 모바일 앱 형태가 잡혀 있음
- 홈, 분석, 기록, 추천, 가이드 같은 핵심 화면군이 현재 기획과 일치함
- 다음 주 Android 구현의 시각 기준으로 바로 활용 가능함

### 수정 필요한 것

- 로드맵 문서와 피그마 화면 설명이 아직 완전히 연결돼 있지 않음
- 필수 화면 전체 목록과 피그마에 나온 화면을 1:1로 대응시켜 문서화해야 함
- 어떤 화면이 1순위 구현인지 표시가 필요함

### 빠진 것

- 화면 구조 설명 문서
- 화면 흐름 확정본
- 버튼/입력/결과 요소별 기능 설명

### 판단

- 피그마 자체는 현재 방향과 잘 맞는다
- 다만 `화면이 있다`에서 끝나지 말고 `개발 가능한 화면 명세`로 바꾸는 작업이 더 필요하다

## 김우영

### 확인된 결과물

- `기능 메모 정리본.wy`
- `데이터 항목 정리본.wy`
- `알람, 설정 문구.wy`
- `백그라운드 감지 기능의 기술 리스크.md`
- 노션 카드 본문 다수

### 노션 본문에서 맞는 것

- 위험 감지 알림 문구
- 설정 문구
- 대응 안내 문구
- 추천 기관/공공지원 연결 방향
- 위험 표현 DB와 위험 유형 DB 구상
- SafeLink 2.0 설명 방향

### 로컬/GitHub 파일에서 수정 필요한 것

- `기능 메모 정리본.wy`는 URL 검사 앱 기준 내용이어서 현재 기획과 맞지 않음
- `데이터 항목 정리본.wy`도 URL, SSL, 도메인, 차단 목록 중심이라 현재 기획과 맞지 않음
- `알람, 설정 문구.wy` 역시 위험 대화 감지 앱이 아니라 URL 검사 앱 문구 기준으로 되어 있어 수정 필요

### 맞는 것

- `백그라운드 감지 기능의 기술 리스크.md`는 현재 SafeLink 방향과 잘 맞음
- 노션 안 최신 카드 내용은 현재 기획과 대체로 일치함

### 빠진 것

- `institutions.json` 구조 초안
- 현재 기획 기준으로 다시 쓴 기능 메모 정리본
- 현재 기획 기준으로 다시 쓴 데이터 항목 정리본
- 현재 기획 기준으로 다시 쓴 알림/설정 문구 정리본

### 판단

- 김우영 결과물은 `노션 최신 내용은 맞고`, `GitHub/로컬 일부 파일은 옛 방향이 남아 있음`
- 지금 가장 먼저 정리해야 할 어긋남은 이 부분이다

## 이번 점검의 핵심 결론

- 팀원 결과물이 아예 없는 상태는 아니다
- 다만 `있는 결과물들이 전부 같은 방향을 보고 있지는 않다`
- 지금 가장 큰 문제는 `노션 최신 기획`과 `일부 GitHub/로컬 문서` 사이의 불일치다
- 따라서 이번 주 남은 작업은 새로 처음부터 만드는 게 아니라, `맞는 초안은 살리고`, `옛 방향 문서는 현재 SafeLink 방향으로 고쳐서 기준을 하나로 맞추는 것`이다
